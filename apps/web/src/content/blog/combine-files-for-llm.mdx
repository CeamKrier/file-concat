## The problem

You have a folder of files and a chat box that takes one block of text. Pasting them
one at a time loses structure, blows past what you can track, and gives the model no
sense of how the files relate.

<Callout type="note" title="What counts as one prompt">
  Most chat boxes take a single block of text. The job is to turn many files into one
  block that still tells the model where each file starts and ends.
</Callout>

## Three ways to do it

<Steps>
  <Step title="Copy and paste by hand">
    Fine for two or three files. Painful past that, and you lose the paths that tell
    the model what it is looking at.
  </Step>
  <Step title="A cat pipeline">
    `cat src/**/*.ts` gets you the bytes, but no file headers, no filtering of lock
    files and build output, and no token count.
  </Step>
  <Step title="FileConcat">
    Drop the folder, let the noise get filtered out, and copy one structured document
    with every path labeled and the token cost shown up front.
  </Step>
</Steps>

## What the structure buys you

An LLM reads a bundle better when each file is clearly delimited and named. That is the
difference between a wall of text and a project it can navigate.

<BeforeAfter>
  <Before label="cat src/*.ts">{`export function add(a, b) {
  return a + b
}
export function sub(a, b) {
  return a - b
}`}</Before>
  <After label="project.xml" tokens="1,204">{`<file path="src/math.ts">
export function add(a, b) {
  return a + b
}
</file>`}</After>
</BeforeAfter>

<Callout type="warn" title="Paths matter more than you think">
  Without the file paths, the model cannot tell an entry point from a helper. The
  labels are the cheapest context you can give it.
</Callout>
