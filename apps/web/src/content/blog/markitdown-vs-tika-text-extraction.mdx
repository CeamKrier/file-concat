A text extractor can hand back clean text and still drop the comment in the margin, the chart's
title or the page header, or let a deleted paragraph back in. We hid a marker in every place 17
file formats can hold text, ran the same files through FileConcat, Apache Tika and Microsoft's
markitdown, and counted what came back.

## Markitdown vs Tika vs FileConcat: which reads more of each format?

FileConcat 2.6, in every format but ebooks. Of the other two, Tika reads more, and markitdown reads
no OpenDocument file at all.

Each score is the share of what a reader of the file sees that came back. A construct found in most
real files counts more than one found in few, so a spreadsheet's page header outweighs a chart's
axis title.

**How it was scored:** a marker in each construct. A visible construct counts when its marker comes
back, a hidden or deleted one when it stays out.

## What does each extractor leave out?

markitdown leaves out comments, page headers and link addresses. Tika reads more of them, but also
prints what the author deleted or hid.

## Which files does each tool fail to read at all?

Text in an old encoding, logs padded with zero bytes, and compiled files posing as text. FileConcat
reads or names all of them, and every other tool misses a few.

<Bars
  title={coverage.corpus.title}
  rows={coverage.corpus.rows}
  ours="FileConcat 2.6"
  note="FileConcat's own test set of hard files: lock files, XML in every Unicode form, logs with ANSI codes and zero bytes, text in legacy encodings, bytecode, a text file with a binary tail. A text file passes when 90% of its words come back, a binary file when the tool says it cannot read it"
/>

The misses take three shapes. Tika returns nothing for a binary lock file, prints compiled Lua and a
DRM-locked ebook chapter as garbage, and garbles Turkish saved in an old Windows encoding.
markitdown stops with an error on two build logs, and for a text file with binary data after it
returns the word None. FileConcat 2.3 misread most of the legacy-encoded files.

**How it reads:** the first bytes decide whether a file is a document, an archive, text or binary.
Text in an unknown encoding goes to chardetng, the detector Firefox uses.

## Where does FileConcat still lose?

On three constructs. One is a choice, two are open.

1. **Ebook authors.** markitdown names the book's author. FileConcat leaves document authors out on
   purpose, the same way in every format. Three in four real ebooks carry one, which costs about a
   tenth of the ebook score and is why markitdown leads that row.
2. **A PDF line drawn invisible.** Tika and markitdown print a line set to invisible on an ordinary
   page. FileConcat drops it. It is rare in real PDFs.
3. **A PDF comment flagged hidden.** It still comes back. None of the real PDFs we sampled had one.

Every format FileConcat reads, and how, is on [the formats page](/docs/formats). Your files are not
uploaded to us, the whole thing runs in your browser.

## How we ran it

Each probe file went through each tool once, on one machine, one process per file with a 300 second
limit. FileConcat ran its web reading chain in Node, with HTML through the web app's own reader.
Tika ran as `java -jar tika-app-3.3.2.jar --text`. markitdown ran as its command line, installed with
`uvx --from 'markitdown[all]==0.1.5'`.

The rule was written before any total was read. A visible construct counts when every one of its
markers is in the output. A hidden or deleted one counts when its marker is absent and the same file
gave output with at least one other marker, so a tool that reads nothing earns nothing for keeping
things out. A crash, an empty output or an unsupported format scores zero. Where the map gives a
construct two parts with different answers, a name to hide and a text to show, each part is held to
its own.

Raw source counts as not read. markitdown prints email and RTF as the file's own text, and Tika
prints a notebook as its JSON. Counted as text instead, they score:

| Count | FileConcat 2.6 | FileConcat 2.3 | Tika 3.3.2 | markitdown 0.1.5 |
| --- | --- | --- | --- | --- |
| Weighted mean, raw source not read | **90.9** | 79.3 | 72.9 | 41.5 |
| Weighted mean, raw source as text | **90.9** | 79.3 | 72.9 | 54.8 |
| Constructs read, raw source not read | **92.7%** | 63.7% | 67.7% | 35.0% |
| Constructs read, raw source as text | **92.7%** | 63.7% | 69.6% | 50.6% |

Counted as text, markitdown's RTF scores 89.5 weighted, above FileConcat's 85.6, because control
words leave the marker strings intact. That is the case the rule exists for.

We also judged FileConcat 2.6's output by hand, construct by construct. The automatic rule disagrees
on 45 of 648. It credits 6 that the hand judgment does not, on layout and reading order, which
marker presence cannot see. It misses 39 that the hand judgment counts as handled, most of them
document properties FileConcat leaves out by design. Every column in this post uses the automatic
rule, so the comparison is like for like. One automatic miss is the rule's own: a formula with a TeX
source is printed as its TeX, and the probe's TeX held only a marker.

Hidden and deleted text: 130 constructs carry a "keep it out" answer. FileConcat 2.6 keeps 115 out,
FileConcat 2.3 97, Tika 62 and markitdown 45. markitdown's figure is low partly because a format it
does not read earns nothing for keeping things out.

FileConcat's losses, sized on the real files: the ebook author is in 76.0% of 200 ebooks and worth
11.6 points of the ebook score. An invisible line of PDF text is on 0.5% of 195 PDFs, worth
0.1 points. No sampled PDF had a hidden comment.

## The hard files, case by case

The 45 cases are FileConcat's own test set for files that are hard to tell or hard to decode, built
in memory from a seeded generator so no binary is committed. Extractors pass a text case when 90% of
its words come back with tags stripped, and a binary case only when they say they cannot read it.
Empty output or garbage fails. The empty file passes on empty output. file, git and ripgrep pass when
their text-or-binary call is right.

| Tool | Passed | Failed cases |
| --- | --- | --- |
| FileConcat 2.6 | **45** | none |
| markitdown 0.1.5 | 41 | log-spinner, log-nul-head, xhtml-drm, big-text-then-binary |
| file 5.45 | 39 | xml-utf16le-nobom, xml-utf16be-nobom, log-nul-tail, log-nul-head, log-nul-sparse, xhtml-utf16le-nobom-cjk |
| Tika 3.3.2 | 38 | lock-gradle, lock-git-index, frag-flutter-compiled, xhtml-drm, txt-cp1254, lua-bytecode, lua-luajit |
| ripgrep 15.2.0 | 38 | lock-gradle, lock-git-index, xml-android-binary, frag-flutter-compiled, xhtml-drm, lua-bytecode, lua-luajit |
| git 2.43.0 | 35 | xml-utf16le/be-bom, xml-utf16le/be-nobom, log-nul-head, log-nul-sparse, xhtml-utf16le-bom, xhtml-utf16le-nobom-cjk, txt-utf32le-bom, txt-utf32be-bom |
| FileConcat 2.3 | 28 | xml-latin1, log-nul-head, xhtml-cp1252/shiftjis/gbk/cp1251/euckr, txt-shiftjis/gbk/cp1251/euckr/cp1254/latin1, css-cp1251-comments, lua-gbk-strings, txt-utf32le-bom, txt-utf32be-bom |

FileConcat ran each tree's own byte router and text classifier on every file, with the encoding
detector where the tree has one (2.6 yes, 2.3 no). Without it, 2.6 passes 38: the seven
legacy-encoding cases need the detector. ripgrep searches a file named on its command line even when
it is binary, so its binary misses follow its design for explicit paths.

## Limitations

- **Home field.** The probes were written for FileConcat's own coverage map, and FileConcat was
  fixed against that map between 2.3 and 2.6. The hard files are its own test set. The one
  counterweight is small: the xls and ppt probes were written with Apache POI, the library Tika
  reads those formats with, and Tika still scores 70 and 88 on them against FileConcat's 100.
- **Presence, not order.** A construct counts when its marker comes back. Reading order, wrapping
  and whether a comment is labelled as one are not scored, which is why the hand judgment
  disagrees on 45 constructs.
- **Weights for 11 formats.** The weighted table rests on 65 to 200 real files per format, from
  one Common Crawl sample. Outlook, the 97-2003 formats, notebooks and subtitles have no weights.
- **Word 97 .doc is out.** Its constructs carry no markers, so it is in neither table.
- **One run.** One machine, one pass, no timing.
- **Repositories not counted.** A fix in this version for files whose binary data starts late
  changed no verdict across fresh clones of 60 public repositories, 39,229 files, since fresh clones
  hold almost no compiled files. It is not in these numbers.

## Reproduce it

Everything but the Tika jar is in the repository: the probes, the scorers, the parsed constructs
and the real-file counts behind the weights.


## Frequently asked questions

**Is markitdown or Tika better for text extraction?**
Tika read more on our probes: 67.7% of marked constructs against markitdown's 35.0%, and 72.9
against 41.5 weighted by real files. markitdown led on ebooks. Tika also printed deleted and hidden
text that markitdown kept out.

**Does markitdown read OpenDocument files?**
No. markitdown 0.1.5 stops on odt, ods and odp with "No converter attempted a conversion". It also
does not read PowerPoint 97 files.

**Does Apache Tika include tracked changes in the text?**
Yes. Deleted text in Word and RTF files comes back in the body, run into the surrounding sentence,
with nothing to mark it as deleted. FileConcat keeps it out.

**Can I get Word comments and PowerPoint notes into the text?**
FileConcat 2.6 reads comments with their authors in Word, PowerPoint, Excel, OpenDocument and RTF,
and the comments on a PDF. In our probes Tika returned a Word comment without its author and missed
comments in PowerPoint's current format. markitdown returned neither.

**Do these tools upload my files?**
Tika and markitdown run on your machine. FileConcat runs in your browser: your files are not
uploaded to us. What you then paste into an assistant is your own choice, but preparing the file
uploads nothing.
