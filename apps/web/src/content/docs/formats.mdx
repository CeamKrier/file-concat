# What FileConcat reads

Anything that is already text, such as source code, markdown, CSV, JSON or logs, goes into the
bundle as it is. The formats below hold their text inside a container, and FileConcat reads it out
in your browser. Your files are not uploaded to us.

A file is recognised by its first bytes, not its name, so a renamed or extensionless document is
still read. Most formats are read as soon as you drop them. Images and recordings wait until you
ask, because recognition and transcription take seconds to minutes. A recording also needs a
speech model downloaded once, which the [privacy page](/privacy) describes.

A document's own title, when its properties hold one, comes first as `[Title: ...]`. The author's
name and the other properties are left out.

A picture's alternative text, the words its author wrote for a reader who cannot see it, comes
through as `[Image: ...]` where the picture sits (in a saved web page, as a Markdown image), and a table's caption and description as
`[Table: ...]` above the table. In a PDF the figures' text follows the page it is on. A picture
with no alternative text, or only a default name such as "Picture 3", is still left out.

A link comes through as `[text](address)` where it sits, in documents, slides, PDFs and email. In a
spreadsheet the cells come first, then each linked cell as `[Link, B2: address]`. A link to another
place in the same file, or one whose text already is its address, is written as plain text.

Each entry also says what is left out, so you know what the model will not see before you paste.
How well each one reads against other tools, at the latest version measured, is on
[the benchmarks page](/benchmarks). The studies behind it are
[the extraction benchmark](/blog/browser-text-extraction-benchmark) and, for how much of each format comes
through comment by comment and chart by chart against Apache Tika and markitdown,
[markitdown vs Tika](/blog/markitdown-vs-tika-text-extraction).
